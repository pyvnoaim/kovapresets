### Scenario auto-apply is gone

1.1.0 shipped presets that switch themselves per scenario. In real use the
mechanism was wrong: the only moment the game tells anyone anything is when a
run *ends* (the stats file write), so the switch always landed after the run it
was meant for. A preset that applies itself once your score is already on the
board isn't automation, it's noise — so rather than ship another approximation,
the feature is removed. Hotkeys, the after-apply re-enter/restart options, and
the tray menu remain the ways to switch.

If you had scenarios assigned to presets, those assignments are simply dropped.
The presets themselves are untouched.

### Presets no longer carry HUD colors or HUD layout

Verified in-game: KovaaK's reads its HUD color file (`Palette.ini`) exactly
once, at launch, and never again — no settings visit, no scenario load, nothing
makes an external change visible mid-session. So per-preset HUD colors could
only ever land "on next game quit", which read as the feature silently not
working. Same story for per-preset HUD layouts. Both are out of presets now;
what a preset holds — crosshair, theme, sounds, sens, DPI — is exactly what
provably applies.

The **HUD editor stays**. Layouts you save there still apply immediately while
the game is closed, or queue for its next quit — and "Restore original setup"
now covers layouts saved before your first preset apply, too.

Existing presets migrate automatically; there's nothing to redo.

### Under the hood

A codebase-wide cleanup rode along: deduplicated apply paths, cheaper
change-detection and idle polling, and a few hundred lines of dead code
removed. No behavior changes beyond the above.
