### Presets that switch themselves, per scenario

Every preset row has a new target icon: assign scenarios to it, and the preset
applies itself. The moment a run ends, KovaPresets works out which scenario is
up next — and if a preset is assigned to it, it's applied before the next
scenario loads, so the crosshair and sounds are already right when it does.
No hotkey, no alt-tab, no hands.

It's playlist-aware. Grinding a benchmark playlist, "up next" follows the
playlist: finish your Pasu runs and the preset assigned to Popcorn is applied
while you're still on the score screen. Outside a playlist it re-asserts the
preset assigned to the scenario you're grinding. Scenario suggestions in the
assignment dialog come from your loaded playlist and recent history — or type
any name. One scenario drives one preset; assigning it elsewhere moves it,
same as hotkeys.

Two honest limits. It triggers when a run *ends* (that's when the game writes
anything to disk), so the very first scenario of a session uses whatever's
active — from the first score screen on, it's automatic. And it deliberately
never re-enters or restarts anything for you, even if that's your after-apply
setting: mid-playlist, hijacking the game's own navigation would be worse than
waiting one scenario load.

### Fixed: switching back to the preset you launched with

Applying preset A mid-session and then returning to the one the game started
with read as "nothing changed" — so the live theme never switched back, and A's
theme stayed on screen. The change detection now compares theme fields against
what the game is actually rendering (the proxy theme file) instead of the
settings file it only reads at launch. Going back works like going forward.

### Under the hood

- **Every settings write is now atomic** — written to a temp file and renamed
  into place. The game re-reads these files at moments KovaPresets doesn't
  control (the proxy theme on menu-open, weaponsettings on scenario entry), and
  a write caught halfway could be read as a truncated file. That can't happen
  anymore, and the same protection now covers the preset store itself.
- **There's a log file.** Applies, queued flushes, restarts, auto-switch
  decisions and errors land in `kovapresets.log` — tray → "Open log file". If
  something ever silently doesn't apply, there's finally something to look at.
