A maintenance release. Nothing changes about how presets behave — if 2.0.0 is
working for you, this is a quiet upgrade.

### Fixed: settings that reset themselves

`settings.json` was the one store still written non-atomically. If a write was
interrupted — a crash, a power cut, a hard shutdown mid-save — it read back as
invalid JSON on the next start, and invalid JSON falls through to defaults:
first-run wizard again, after-apply mode back to "Do nothing". It's written to
a temp file and renamed into place now, the same way presets and every game
file already were.

Also fixed: on macOS and Linux the tray icon fails to decode, and that threw
out of startup — taking auto-update, the queued-apply flush and hotkey
registration with it, with nothing on screen to say why. Windows was never
affected; dev runs on other platforms no longer come up half-booted.

### Under the hood

The theme mapping used to be two hand-written lists of the same 30 fields in
opposite directions, so adding a field to one and forgetting the other would
silently drop it from every applied preset. Both directions now read from one
table, and the self-test round-trips a preset through the proxy theme file and
back — a row that maps only one way fails the test.

Verified against a real install across 55 themes: the theme files this version
writes are field-for-field identical to 2.0.0's.

Plus CI on Windows and Linux, ESLint, and a `CONTRIBUTING.md` for anyone who
wants to poke at it.
