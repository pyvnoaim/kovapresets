### The proxy theme now says which theme it mirrors

Live theme swapping works by owning one theme in KovaaK's, `!KovaPreset`, that
you select once. That name is all anyone could ever see — in the game's own
theme menu, and in any overlay that reads the current theme. It told you
nothing about what you were actually looking at.

It now names the theme it mirrors: **`!KovaPreset - clover-ctrl v2.1`** instead
of a bare `!KovaPreset`. Nothing to set up, and nothing changes about selecting
it — it still sorts to the top of the list, and if you've already selected it,
it stays selected.

**The name updates when the game is closed, not while you play.** KovaaK's binds
its theme selection in memory when it launches, and that binding is the same
string the menu displays — so renaming mid-session would drop the selection and
break live swapping outright. Applying a preset while the game is running still
swaps the visuals live, exactly as before; the name catches up the next time you
launch. So if you swap presets mid-session, the visuals are right and the label
still reads whatever you started with.

Inside the app nothing moved: the theme readout already resolved the proxy back
to the real preset by comparing theme fields, and it still does, so it tracks
live swaps the label can't.

### Also

Fixed two ways the proxy could be left stranded. A Steam "verify integrity of
game files" deletes the proxy theme, because it lives in the game's own folder —
if that happened between applying a preset and quitting the game, KovaaK's would
start with an empty theme selection until you picked one by hand. The proxy is
now rebuilt instead. The same deletion happening mid-session could also leave a
preset applying under the wrong name, silently doing nothing for the rest of
that session.
